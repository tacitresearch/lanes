| rookery (`examples/rookery`, a package of its own) | A small social network for bots and their owners as a web application with a JSON API: sign-up, log-in, sessions, API tokens, posts, follows, timelines, deletes and a rate limit, all in one actor that runs the spec's functions; the spec model-checked alone and the system against it on two accounts, with timers firing at any moment, crashes, and requests lost and reordered; three seeded bugs (fan-out on write that keeps a deleted post, a delete by another account, a rate limit off by one) found; runs on `Http.serve` with a journal and snapshots and is tested over HTTP through SIGKILL and a restart (`rookeryLive`) | Posts never lost and deleted only by their author, a deleted post in no read, timelines exactly the newest posts of the accounts followed, the rate limit, API changes acted on once per `seq`, no reply with another account's secrets, every bound, for every configuration (`examples/rookery/Rookery/Proofs/`); the system implements its spec with deadlines in every environment whose link from the outside does not duplicate (`Rookery.implements`); of every run of the system, through the history `System.Implements.history` gives, no response carries another account's secrets, every list of posts is a read of a board the spec reaches, and a post deleted through the web is in no read asked for after the delete was answered, with distinct request ids (`Rookery.output_secret`, `Rookery.output_read`, `Rookery.deleted_unread`); and, with distinct request ids, a post answered `posted` to a web post or shown in a read is in the board of every later read until a delete of it arrives, after a pass of an account's window and before the next its web posts are answered `posted` with at most `maxPerWindow` ids, and of the API changes of one account with one `seq` every reply but `stale` and `badToken` is the same (`Rookery.posted_kept`, `Rookery.shown_kept`, `Rookery.rate_limit_run`, `Rookery.api_once`). Not yet: an API post's `posted` as a statement about runs (a repeated `seq` is answered from the memo), the gate in front as a refinement, the bridge (tested), liveness.
