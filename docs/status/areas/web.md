- Templates take text children as string literals (`<p>"text"</p>`), not bare text.
- The gate keeps waiting requests in a list, so each request costs time linear in `maxPending`.
- Behind `Http.serveShard` a response must be put out by an actor of the process that took the
  request. Request ids are each process's own, so a response put out on another shard reaches
  that shard's gate, which may be waiting on the same id for another client. Nothing prevents
  this; `Tests/Fronted.lean` shows the mild case, a `504` at the front that took the request.
- Templates cannot contain inline `<script>` or `<style>` text, and `render` gives those
  elements no children; URL attributes accept only relative, `http`, `https`, `mailto` and `tel`
  URLs. An attribute that holds code or markup (`onclick`, `srcdoc`, `style`) takes its value as
  given, escaped: what it means is the application's.
- The browser model of `Html.lex_render` is the tokenizer's data and double-quoted-attribute
  states: a browser also lowercases names, keeps the first of two attributes of one name, and
  reads the content of `title`, `textarea`, `noscript` and the other raw text elements as text.
- A purpose of `Auth.sign` must have no zero byte, and `form` is the purpose of form tokens.
- The server writes no `Date` header, and answers an unknown method `501`.
- The head of a request, and a chunked body, is read again from its start each time bytes of
  it arrive, so one sent a byte at a time costs time quadratic in its length, within its limit
  and its deadline.
- A response streams to an HTTP/1.0 client in chunks, which it does not read. A body that
  streams is no longer handed on once the client ends its side. That the pieces of a whole run
  make up the body, and the bytes of a whole stream the parts given, is model-checked, not proved.
