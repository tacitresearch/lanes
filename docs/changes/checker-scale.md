### Added

- A fingerprinted mode of the checker, off by default (`Check.fingerprint`, `Check.systemFingerprinted`): it keeps a 64-bit hash of each state seen, and of each state stored the record of its parent and the transition that led to it, so states are held only while their level waits. A video's life in `examples/videos` takes 48 s and 530 MB, against 79 s and 1,518 MB exact, over the same 1,838,171 states. A pass is not exhaustive and the report says "fingerprinted"; every trace it reports is replayed from its choices and checked again, so a violation, a deadlock or a witness is real (`Check.fingerprint_violated`, `Check.systemFingerprinted_violated`). With `Options.tasks` it computes each level's successors in tasks, proved the same function (`Fingerprint.Search.runParallel_eq`); on four shared cores that does not help. `docs/decisions/D92-checker-scale.md` has the profile and the numbers.
- Reduced checks (`Model.reduce`, `Check.systemReduced`): each state replaced by a representative. A complete pass under a `Model.Reduction` is a pass of the model for invariants, refinement checks and deadlocks, and what it reports is true of a related reachable state (`Check.search_reduce_sound`, `Check.search_reduce_deadlock_free`, `Check.systemReduced_sound`). `Check.World.Reduction.ofDriver` gives one for a driver's state kept in a canonical form under a relation the driver cannot see (`Driver.Simulation`).

### Fixed

- The checker's hash summed over the messages in flight, so states that differed only in the order of the messages on an ordered link collided: 13% of the states stored in two videos scenarios and 20% in a third. Each message on an ordered link is now hashed with its place on it (`Check.Node.trafficHash`); states the checker merges keep one hash (`Check.Node.trafficHash_eq`), and the videos checks have no collision left.
